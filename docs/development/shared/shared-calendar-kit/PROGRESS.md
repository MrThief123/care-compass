- Visual QA fix, round 8 (human review, pre-PR): human sent a screenshot of a `full`-tier day block whose time range was clipped through the middle of its digits while the assignee and `Planned` pill below it were intact — "let's fix that out so that planned tags can also vary in size and don't block things". Measuring the rendered DOM found **two independent defects, neither visible to any unit test**. **See DECISIONS.md FD-07.** (1) `cn` was deleting the type ramp: tailwind-merge only knows Tailwind's own utilities, so it read the `@utility text-body-small` in `tokens.css` as a text *colour* and let any `text-<colour>` in the same call delete it — `cn("text-body-small", "text-text-primary")` returned `"text-text-primary"`. Every affected element fell back to the inherited 14/21 body type instead of 13/18, and `StatusPill` rendered 31px instead of 28px, so round 7's block arithmetic was measured against a ramp that never reached the DOM. Fixed in `src/lib/utils.ts` with `extendTailwindMerge`, registering the ten type tokens in the `font-size` group. (2) The time row carried `truncate`, whose `overflow: hidden` waives a flex item's automatic minimum size — so when the stack overflowed, flexbox shrank *the time row* rather than the title, exactly backwards. The time row, the day view's status row and the week view's assignee line are now `shrink-0` and the title row `min-h-0`, so whatever height a pill actually renders at, it costs the title a line instead of cutting the time in half; that is what answers "tags can vary in size" for pills this round did not anticipate. Block metrics are now **derived rather than written down**: `block-density.ts` exports `BLOCK_BORDER_PX` (2 — blocks are border-box and the border was never counted), `BLOCK_PADDING_PX`, `TITLE_LINE_PX`, `TIME_LINE_PX`, `DETAIL_LINE_PX`, `STATUS_ROW_PX` and `BLOCK_CHROME_PX`, and the tier thresholds are built from them, so a tier can no longer begin below the height its own content needs. Also fixed a 1px overflow on every 22px `compact` block: a 14px status icon baselined against 13px text stands taller than the text's line box, so the icon is now `self-center` and the tier's `py-0.5` is gone. **HUMAN REVIEW: test expectations changed** — `blockDensity(72)` was `"full"` and is now `"regular"` (the `full` boundary moved 72→75, `regular` 40→43; in both bands the old tier clipped its own last row), and `titleLines(88, 54) === 2` became `titleLines(88, 58) === 1` (the function is unchanged; its inputs were wrong). Full before/after in DECISIONS.md FD-07. Confirmed by a scripted DOM audit at 1440/1100/820/700px across all three views — no block's stack overflows, no row is squeezed below its line box, no title renders a fractional line, zero console/page errors — plus screenshots of the reported block at 900px and 640px. `npm run verify` green (lint, typecheck, format, 212 passed / 1 skipped; calendar kit alone 95/95).
