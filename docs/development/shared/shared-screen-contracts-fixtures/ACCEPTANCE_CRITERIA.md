# Acceptance Criteria — UI-04 Screen data contracts and fixtures: full-history Task log, single occurrence, event documents

Each criterion is observable and maps to at least one test in TEST_PLAN.md. Criteria may not be changed after implementation starts without a controlled change recorded in DECISIONS.md.

| ID | Story | Type | Criterion (Given / When / Then) | Status |
|---|---|---|---|---|
| AC-01 | US-01 | happy | Given Margaret's occurrences, when `getTaskLog` is read page by page, then rows are newest first by `start` instant (instants, not strings), ties broken by `key` ascending; the pages concatenate into one strictly ordered list with no gaps or duplicates; two reads return the same order. | NOT MET |
| AC-02 | US-01 | edge | Given page size 20, when the (filtered) log has 0, 1, exactly 20, 21 or 40 rows, or a page beyond the last is requested, then `items`, `page`, `pageSize` (20) and `total` are correct and nothing throws; a page beyond the last returns `items: []`, the true `total` and the requested `page`. | NOT MET |
| AC-03 | US-01 | validation | Given `page` of 0, -1, 1.5, NaN or Infinity, or `status` of 'bogus', when `getTaskLog` is called, then it rejects with a Zod validation error; an omitted page means 1; a very large valid page returns an empty page. | NOT MET |
| AC-04 | US-01 | happy | Given `q` and/or `status`, when applied, then `total` counts only rows matching both across the whole history (`q`: trimmed, case-insensitive substring of the title; `status`: exact) and pages are pages of the filtered set; a `q` with no match gives `total` 0. | NOT MET |
| AC-05 | US-01 | permission | Given a key for one of Margaret's past (done or overdue) or planned occurrences, when `getOccurrence(clientId, key)` is called, then that occurrence is returned; an unknown key, an unknown client, or another client's key (in either direction) returns `undefined`, and no other client's row is ever returned. | NOT MET |
| AC-06 | US-01 | permission | Given `getEventDocuments(clientId, eventId)`, when called, then it returns that client's documents attached to that event (name, mimeType, sizeBytes, uploadedAt, uploadedBy), oldest upload first; an event with none returns `[]`; an event of another client returns `[]`; an event with several returns all of them. | NOT MET |
| AC-07 | US-02 | error | Given DATA_SOURCE=supabase, when `getOccurrence` or `getEventDocuments` is called, then it throws the not-implemented error naming its domain and function. | NOT MET |
| AC-08 | US-02 | happy | Given the mock data source, when Margaret is read through the contracts, then the header is '78 years' / 'Preston VIC' / 'Banksia Home Care'; the Task log holds exactly the nine design rows for 26–30 Nov 2026; Overdue is exactly Weekly weigh-in and Medication review with no nurse; the five newest done-or-overdue rows are the design's Recent activity rows; Morning medication is Done by Aisha Rahman, completed at 09:14, with the design description and 'Medication chart.pdf'. | NOT MET |
| AC-09 | US-02 | edge | Given the fixtures, when the Task log is paged, then Margaret has at least 120 completed occurrences before 26 Nov 2026 (137 rows in total, 7 pages, last page 17), including a task title of about 100 characters and a carer full name of about 50 characters, both on page 1. | NOT MET |
| AC-10 | US-02 | security | Given all fixtures, then occurrence keys are unique across clients and equal `eventId:start`; each occurrence's client and event exist and agree; Done rows have an actor and completion time, others have neither; actors and assignees are known staff full names or a listed temporary carer; every document belongs to an existing event of its own client; repeated reads and fresh module loads return identical data; the other clients' data stays valid. | NOT MET |

Status values: NOT MET · MET (test passing) · BLOCKED (cite OQ/PD).
