# Acceptance Criteria — ADM-05 Admin — Remove client

Each criterion is observable and maps to at least one test in TEST_PLAN.md. Criteria may not be changed after implementation starts without a controlled change recorded in DECISIONS.md.

AC-01 and AC-02 are the originals. AC-03 to AC-10 were added before implementation started, from the human's answers on 2026-10-03 (FD-02, FD-04). "Doris", "Priya" and "Tom" in AC-01/AC-02 are any client, admin and family member; the tests use their own fixtures.

| ID | Story | Type | Criterion (Given / When / Then) | Status |
|---|---|---|---|---|
| AC-01 | US-01 | happy | Given Priya removes Doris, when Banksia carers query Doris, then zero rows are returned. | NOT MET |
| AC-02 | US-01 | happy | Given Doris removed, when Tom (family) queries Doris's events, then all events are returned. | NOT MET |
| AC-03 | US-01 | happy | Given an admin removes a client, when the function returns, then the client row is kept with organisation_id null and organisation_removed_at set; its future shifts are cancelled, the shift running now ends now; past and already-cancelled shifts, other clients' shifts, and the client's events, completions, budget, documents and family links are unchanged. | NOT MET |
| AC-04 | US-01 | permission | Given a caller who is not an active admin at AAL2 of the client's organisation (a carer, family, another organisation's admin, an admin without MFA, no session), or a client that is unknown or already removed, when they call admin_remove_client, then it is refused (42501) and nothing changes. The admin of the organisation reads zero rows for the client afterwards. | NOT MET |
| AC-05 | US-01 | happy | Given an admin presses Remove on a client, when the dialog opens, then it names the client and says staff lose access and the family keeps all records; Cancel and Escape do nothing and return focus; Confirm calls removeClient with that client's id, the row leaves the list, a status message says it was removed (no "reset when you reload" text) and focus goes to the list heading. Removing the last client shows the empty state. | NOT MET |
| AC-06 | US-01 | error | Given removeClient fails, when the admin confirms, then the row stays, an alert says it could not be done and the dialog closes; the action itself returns VALIDATION for a blank id, NOT_FOUND for an unknown client in mock mode and NOT_ALLOWED for a refused caller; in mock mode getAdminClients no longer lists a removed client. | NOT MET |
| AC-07 | US-02 | happy | Given a client was removed, when the family reads the client header summary, then organisationRemoved is true and there is no organisation name; a family-created client that never had an organisation reports organisationRemoved false; once the family moves the client to a new organisation, organisation_removed_at is null again and organisationRemoved is false. | NOT MET |
| AC-08 | US-02 | happy | Given organisationRemoved is true, when the family opens Settings, then a banner next to Change organisation says the organisation removed the client and a new one must be chosen, with a Choose organisation button that opens the FAM-13 picker (no organisation marked current), and confirming moves the client and clears the banner. Given organisationRemoved is false, the banner and button are absent, and a client with no organisation still has no Change or Choose button. | NOT MET |
| AC-09 | US-02 | happy | Given organisationRemoved is true, when the family opens Home, then a banner says the organisation removed the client and links to Settings; given it is false, no banner is shown. Both banners have no axe violations and no notification, toast, email or badge is created. | NOT MET |
| AC-10 | US-01 | integration | Given an admin session against local Supabase, when removeClient runs, then the admin list drops the client, a carer session reads nothing, the family session still reads the client and its events and its header reports organisationRemoved true; a carer session calling removeClient is refused and nothing changes. | NOT MET |

Status values: NOT MET · MET (test passing) · BLOCKED (cite OQ/PD).
