| AC-05 | US-01 | happy | Added under CHG-005. Given a log longer than one page (for example 137 tasks), when Task log renders, then it shows that page's rows, 'Showing 1-20 of 137', the current page indicated and Next; Next shows 'Showing 21-40 of 137' with Previous; the last page is reachable and shows only the remaining rows; exactly one page, exactly one page size, one over and zero rows all render correctly. | MET (tests: 137 rows on the real contract, 537 and 5,000 generated rows; paging also driven in a real browser) |
| AC-06 | US-01 | validation | Added under CHG-005. Given invalid or hostile params (page=0, page=-3, page=abc, page=99999, status=bogus, q of 5,000 characters), when Task log loads, then it falls back to page 1, page 1, page 1, the last page, all statuses and a q capped at 200 characters, and never errors. | MET (tests; hostile params also driven in a real browser) |
| AC-07 | US-01 | happy | Added under CHG-005. Given a search or Status change, when it is applied, then the URL carries q / status / page (page reset to 1), so a shared link, reload and Back/Forward show the same view; the search box follows the URL. | MET (component tests with a mocked router; search and Status also driven in a real browser: q and status in the URL) |
| AC-08 | US-01 | happy | Added under CHG-005. Given a Task detail opened from a searched, filtered or paged log, when 'Back to Task log' is used, then it returns to the same q, status and page; links are built only from validated params. | MET (tests; Back also driven in a real browser) |
| AC-09 | US-01 | happy | Added by CHG-014. Given any Task detail, when it renders, then one outlined "Edit event" button sits at the right of the title row and links to the event's Edit event route; the Description card has no Edit link; the button is at least 44×44px, uses tokens only (never white text on #0C9BA9), and wraps below a long title rather than overlapping it at any width from 1920 to 768px. | MET |
| AC-10 | US-01 | happy | Added by CHG-014. Given a task opened from the Calendar, Home or the Task log, when Task detail renders, then Back reads "Back to Calendar", "Back to Home" or "Back to Task log" and returns to the exact view it was opened from (Calendar view, selected day and month; Task log q / status / page). | MET |
| AC-11 | US-01 | validation | Added by CHG-014. Given a missing, unknown or hostile origin (e.g. `from=https://evil.example`) or junk calendar params, when Task detail renders, then Back falls back to "Back to Task log" with any valid Task log params (or, for `from=calendar`, to the calendar's defaults); the Back href is built only from a whitelisted origin and re-validated params and never contains a value read raw from the URL. | MET |
